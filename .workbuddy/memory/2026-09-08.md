## UI 设计评审（BusinessTalking）

对 `src/app/**` + `src/components/**`（约 5,600 行）做了一次完整 UI 评审，基准是 `docs/prd/DESIGN.md`（Apple 设计语言 token 规范，562 行）。产出 `docs/design/UI_REVIEW.md`。

**核心结论**：规范写得很好，但实现与规范系统性漂移。不是设计能力问题，是规范没被强制执行。

关键量化发现（后续可直接复用）：
- 圆角：规范 4 档（8/11/18/pill），实现渲染出 5 种（6/8/12/16/pill）。**18px 卡片圆角与 11px capsule 使用次数为 0**，全部塌缩到 8px。根因是 Tailwind v4 的 `rounded-lg` = 8px 而 DESIGN.md 的 lg = 18px，语义错配。
- 阴影：规范 1 个（仅产品图），实现 19 种，大量用于卡片/按钮/气泡。
- 强调色：`run-cards.tsx:30` ICON_COLORS 按名称哈希生成 8 色彩虹，违反单一强调色原则。
- 字重：26 处 font-medium(500)，规范明确 500 缺席。
- 字号：15 种任意 px，11px(37 次) / 13px(55 次) 不在规范内；全局 -0.374px 字距被误用到小字。
- 明暗瓦片：tile-1/2/3 + primary-on-dark 仅 3 处引用，Apple 底盘未建立。
- 组件库：Card 引用 0 次，EmptyState 0 次，手写 `<button>` 57 处 vs Button 13 处。
- 响应式：全项目仅 19 处断点类；sidebar 固定 w-56、讨论页 aside 固定 w-[320px] 均无折叠。
- 无障碍：焦点环已全局实现（值得保留）；模态无 role=dialog/Escape/焦点陷阱；图标按钮最小 24px < 44px。

**修复优先级**：P0 = 圆角 token 重定义 + 阴影收敛 + 彩虹色改 tile-1 + 字重 500→600（纯类名改动，不碰业务逻辑，预计一致性 60%→85%）。
