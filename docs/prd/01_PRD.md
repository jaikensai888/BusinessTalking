# BusinessTalking - 产品需求文档

*版本：1.1 | 状态：草稿 | 项目类型：全新项目*

---

## 1. 产品概述

### 1.1 产品定位
一个收录 skill（分析技能）与人格（人格蒸馏产物）、支持把两者编排成"商业可行性分析配方"、内置大模型执行、支持输入驱动式交互与人格一对一交流的个人/小团队自用 Web 工具。

### 1.3 核心痛点
- 网络上有大量 skill（分析技能），但**单个 skill 效果难以评测**，单独使用价值有限
- 不同的 skill 需要**组合使用**才能覆盖完整的可行性分析流程，但缺乏编排工具
- 人格蒸馏类 skill 能提供多视角讨论与启发，但**未被纳入结构化的分析流程**
- 可行性分析容易陷入**确认偏误**（只找支持自己的证据），缺少对抗性视角
- 传统"表单填写式"录入 skill 门槛高，网上生态（npx 命令安装）未被利用

### 1.4 核心价值
把零散的 skill 与人格蒸馏产物，编排成可复用的"可行性分析配方"，通过**输入驱动的工作台**（输入想法 + @配方 引用）一键产出带多视角质询、结构化、可追溯的商业可行性报告；支持 npx 命令便捷导入 skill、与人格一对一交流获得启发；并通过效果反馈机制沉淀"哪些 skill/配方真正有效"的数据。

### 1.5 MVP 目标
用户在本机运行该工具：通过 npx 命令导入 skill、与人格一对一交流获得启发；从收录库中选择 skill 与人格编排成可行性分析配方；在工作台居中输入框输入商业想法（可 @ 引用配方）一键执行；最终获得结构化可行性报告，并能对报告和各步骤进行效果评分。

## 2. 目标用户

| 用户类型 | 背景描述 | 核心需求 | 使用场景 |
| -------- | -------- | -------- | -------- |
| 个人创业者 | 有商业想法，缺乏系统评估方法 | 快速、低成本评估想法可行性 | 有新想法需要判断是否值得投入时 |
| 小团队/创始人 | 团队讨论商业方向，需要结构化论证 | 多视角质询，避免团队确认偏误 | 立项评审、方向决策之前 |
| 商业顾问/分析师（自用） | 为项目做可行性分析，方法需可复用 | 可复用的分析流程与报告输出 | 接到新的咨询/分析任务时 |
| 关注 skill 生态的进阶用户 | 收藏大量 skill，想评估其真实效果 | 便捷导入（npx）、组合编排、与人格对话启发 | 尝试新 skill、构建专属分析流程、头脑风暴时 |

## 3. 功能范围

### 3.2 MVP 范围内 ✅

**工作台（输入驱动）**
- 居中大输入框：输入商业想法，支持 `@配方名` 语法引用配方（输入 @ 弹出配方选择器）
- 提交即启动分析，下方工作区以**卡片流**呈现每次分析会话（执行进度、步骤状态、人格质询、报告摘要；点击卡片展开详情）
- 未引用配方时，提交后弹出配方选择确认

**Skill 库**
- 浏览、搜索、按分类/标签筛选 skill
- 查看 skill 详情：名称、描述、指令内容、输入/输出说明、来源、标签
- 内置 8~12 个精选 skill（商业模式诊断、对标分析、概念拆解、目标清晰化、财务测算框架、SWOT 分析、风险清单、报告综合等）
- 界面手动新增 / 编辑 / 删除 skill
- **通过 npx 命令导入**：输入任意 npx 安装命令（如 `npx skills add xxx`、`npx dbskill`），确认后执行，解析 SKILL.md 自动入库（来源标记 npx，保留执行日志，失败可重试）

**人格库**
- 人格卡片以**头像**形式展示（内置人格配定制插画，自定义人格自动生成头像）
- 浏览、查看人格详情：名称、描述、系统提示词（人格蒸馏产物）、视角类型
- 内置 6~8 个人格（风险投资人、挑剔客户、竞争对手、奥派经济学家、连续创业者、行业分析师等）
- 界面手动新增 / 编辑 / 删除人格
- **与人格一对一交流**：点击人格卡片进入"详情 + 交流"页，多轮对话（人格系统提示词作为角色设定，会话内记忆），会话保存可回看、可导出为 Markdown 笔记

**配方编排**
- 表单式步骤编辑器：创建配方 → 依次添加步骤
- 每个步骤 = 选择 skill + 选择人格（可选，作为该步骤的质询视角）+ 定义输入
- 步骤间自动传递上一步输出
- 配方可保存、编辑、调整步骤顺序、复制、删除

**执行与输出**
- 内置大模型执行：用户自备 API Key，可在设置中接入并切换多家主流大模型服务
- 运行入口：工作台居中输入（主入口）+ 配方详情页"运行"按钮
- 按步骤顺序执行 → 分步展示中间结果（可追溯）
- 最终生成结构化可行性报告（含各视角质询结论），报告导出为 Markdown 文件

**效果反馈**
- 对每个步骤和最终报告打星（1~5 星）+ 备注
- 运行历史：记录历次运行的输入、各步骤结果、最终报告与评分，可随时回看

### 3.3 MVP 范围外 ❌
- 配方分享社区 / 配方市场（原因：个人自用工具，暂无多用户需求）
- 可视化拖拽画布编排（原因：MVP 用表单式步骤编辑跑通流程，可视化画布留待后续迭代）
- 配方分支 / 并行节点（原因：MVP 线性链即可覆盖主要可行性分析场景）
- 账号体系 / 多用户 / 云同步（原因：本地自用，数据私密）
- 大模型费用代付 / 计费（原因：用户自备 API Key）
- 人格对话结论**自动注入**配方执行（原因：MVP 通过导出笔记/手动粘贴实现联动）
- npx 导入源白名单与签名校验（原因：个人工具由用户确认执行即可，风险可控）
- 第三方 skill 自动更新 / 版本管理（原因：MVP 手动重新导入即可）
- 效果数据的统计分析报表（原因：先积累数据，统计分析后续迭代）

## 5. 数据流转

```
工作台居中输入（商业想法 + @配方 引用）
  → 步骤 1（Skill A：目标清晰化 / 概念拆解，可选人格视角）
  → 步骤 2（Skill B：商业模式诊断，可选人格视角）
  → 步骤 3（Skill C：对标分析 / 财务测算，可选人格视角）
  → 步骤 4（人格质询轮：多个人格轮番质询方案）
  → 步骤 5（Skill N：风险清单 / 报告综合）
  → 最终交付：结构化商业可行性报告（工作区卡片呈现，可导出 Markdown）

辅助流：
  Skill 库 ← npx 命令导入（解析 SKILL.md 入库）
  人格库 ← 点击卡片进入一对一交流（对话保存、可导出笔记）
```

## 6. 成功标准

### 6.1 完成标准（Definition of Done）
- [ ] 用户可以浏览、新增、编辑、删除 skill 与人格
- [ ] 用户可以通过 npx 命令导入 skill 并解析入库（含执行日志与失败重试）
- [ ] 用户可以点击人格卡片进行一对一对话，会话保存可回看、可导出
- [ ] 用户可以创建配方，为每个步骤选择 skill 与人格，并保存配方
- [ ] 用户可以在工作台居中输入商业想法（@ 引用配方）启动分析，完整走完所有步骤并生成报告
- [ ] 报告分步展示中间结果，最终报告可导出 Markdown
- [ ] 用户可对步骤与报告评分、备注，运行历史可查

### 6.2 成功指标（KPI）
- 用户能否在 15 分钟内完成"编排配方 → 工作台输入 → 获得报告"的完整闭环
- 配方运行成功率（完整执行到报告生成）
- 用户对最终报告的评分均值（均值 ≥ 4 视为有效）
- 配方复用次数（同一配方运行 ≥ 2 次视为用户认可其效果）
- npx 导入成功率（解析入库成功次数 / 尝试次数）
- 人格交流会话数与导出笔记数（衡量"讨论与启发"价值）

## 7. 风险与约束

| 风险/约束 | 影响程度 | 应对策略 |
| --------- | -------- | -------- |
| 大模型执行效果依赖所选模型质量，输出不稳定 | 中 | 每步要求结构化输出；支持多服务切换对比 |
| skill 指令质量参差，直接执行可能偏离预期 | 中 | 用输入/输出说明约束输出格式；靠反馈评分沉淀"有效"skill |
| 人格提示词写不好会变成无效装饰 | 中 | MVP 内置人格经人工精调；允许用户编辑系统提示词 |
| 长配方多步执行耗时长、消耗 Token 多 | 中 | 支持单步跳过/重试；执行前展示步骤数与预估成本提示 |
| 任意 npx 命令存在供应链安全风险 | 中 | 执行前展示完整命令与风险提示需确认；临时目录沙箱执行、超时限制；仅用户主动触发 |
| 本地单文件存储能力有限 | 低 | 个人自用场景单用户访问，无并发压力 |
