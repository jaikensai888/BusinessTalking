# UX 设计文档

*基于 PRD v1.1 | 视觉基准：DESIGN.md（Apple 设计语言分析）*

---

## 1. 设计概述

### 1.1 设计目标
- 用户在 **15 分钟内**完成"编排配方 → 工作台输入 → 获得可行性报告"的完整闭环
- **输入驱动**：工作台以居中输入框为主视觉，让"输入想法 → 得到分析"成为第一直觉
- 视觉语言遵循 **DESIGN.md（Apple 设计语言）**：单一 Action Blue 强调色、明暗瓦片交替、无装饰阴影、大留白——UI 退后，让"分析内容"本身说话
- 执行过程**透明可追溯**：每一步的输入输出都可见，最终报告可导出
- 人格有头像、可交流，以"画廊式"卡片呈现
- Skill 库**低门槛扩充**：支持 npx 命令一键导入

### 1.2 设计原则
- **单一强调色** - 所有"可点击"信号都是 Action Blue `#0066cc`，不引入第二品牌色
- **明暗交替** - 全宽瓦片在白色/羊皮纸与近黑之间交替，颜色变化本身即分隔
- **无装饰** - 无渐变、无卡片阴影、无装饰边框；层级来自表面色变化与 1px hairline
- **留白为基座** - 内容四周至少 24px 空气，区段用 80px 大间距
- **pill 即动作** - 胶囊形只属于主/次按钮、搜索框与标签等"动作"元素
- **反馈** - 执行中每步状态实时可见（进行中/成功/失败/跳过）；npx 导入日志实时展示
- **容错** - 删除被引用的 skill 前明确警告；npx 命令执行前展示确认；执行失败支持单步重试/跳过

### 1.3 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 个人创业者 | 有想法、时间碎片化 | 输入想法快速看到结构化结论 |
| 小团队创始人 | 需要结构化论证说服他人 | 多视角质询报告，可导出分享 |
| 商业顾问（自用） | 高频分析、流程复用 | 把常用分析套路固化成配方反复使用 |
| skill 生态进阶用户 | 收藏大量 skill | npx 便捷导入、与人格对话启发、组合对比效果 |

## 3. 用户流程

### 3.1 编排配方

**触发条件**：用户想建立一套可复用的可行性分析流程
**目标**：保存一个包含多步骤（skill + 可选人格）的配方

```
[进入配方页] → [新建配方] → [填写名称/描述]
  → [添加步骤] → [选择 skill] → [选择人格(可选)] → [预览输入/输出]
  → [调整顺序/删除步骤] → [保存配方]
                     ↓
              [错误处理：步骤未选 skill 时提示]
```

**步骤说明**

| 步骤 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 1 | 点击"新建配方" | 打开配方编辑器 |
| 2 | 填写名称/描述 | 实时校验必填项 |
| 3 | 点击"添加步骤" | 出现步骤卡片（默认空态） |
| 4 | 选择 skill | 显示 skill 输入/输出说明，辅助判断输入映射 |
| 5 | 选择人格（可跳过） | 显示人格视角说明 |
| 6 | 保存配方 | Toast"已保存"，返回配方列表 |

### 3.2 工作台启动分析（主流程）

**触发条件**：用户有商业想法待评估
**目标**：从工作台输入想法启动分析，获得可行性报告

```
[工作台] → [居中输入框：输入商业想法 + @配方（可选）]
  → [提交] → [未 @ 配方时弹出配方选择确认]
  → [执行] → [下方工作区生成分析卡片（实时更新）]
  → [完成] → [卡片显示报告摘要，点击展开完整报告/导出 Markdown]
              ↓
  [异常：某步失败 → 重试该步 / 跳过该步]
```

**步骤说明**

| 步骤 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 1 | 在居中输入框输入想法 | 输入 @ 弹出配方选择器，选中后插入可删除的配方标签 |
| 2 | 点击"开始分析" | 未引用配方时弹出配方选择确认；有配方直接启动 |
| 3 | 等待执行 | 工作区网格首位插入新竖版卡片：进度条 + 步骤时间线实时更新 |
| 4 | （可选）失败处理 | 卡片内点击"重试"或"跳过" |
| 5 | 查看报告 | 卡片展示报告摘要；点击"展开"查看完整报告 |
| 6 | 点击"导出 Markdown" | 下载 .md 文件 |

### 3.3 npx 导入 Skill

**触发条件**：用户想把网上的 skill 装进自己的库
**目标**：通过 npx 命令导入并解析入库

```
[Skill 库] → [点击"通过 npx 导入"]
  → [输入命令（如 npx skills add xxx）]
  → [展示命令预览 + 风险提示] → [确认执行]
  → [执行日志实时展示] → [解析结果预览（skill 名称/描述/指令片段）]
  → [勾选确认入库] → [Toast 导入成功]
              ↓
  [失败：日志可见，可修改命令重试]
```

**步骤说明**

| 步骤 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 1 | 点击"通过 npx 导入" | 打开导入弹窗，预填示例命令 |
| 2 | 输入命令 | 实时显示命令预览与风险提示 |
| 3 | 确认执行 | 弹窗内展示执行日志（流式） |
| 4 | 查看解析结果 | 展示候选 skill 卡片（名称/描述/指令片段），可勾选 |
| 5 | 确认入库 | Toast"已导入 N 个 skill"，列表刷新 |
| 6 | 失败处理 | 日志区显示错误原因，可修改命令重试 |

### 3.4 与人格交流

**触发条件**：用户想与某个人格一对一讨论获得启发
**目标**：完成一次多轮对话，可保存回看

```
[人格库] → [点击人格头像卡片] → [人格页"交流"Tab]
  → [输入消息] → [人格以角色设定回复]
  → [多轮对话] → [导出笔记 / 保存会话]
```

**步骤说明**

| 步骤 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 1 | 点击人格卡片 | 进入人格页（默认"详情"Tab） |
| 2 | 切换到"交流"Tab | 显示会话列表（若有历史）+ 对话区 |
| 3 | 输入消息发送 | 气泡消息流式回复，会话内保持人格角色 |
| 4 | 新会话 | 点击"新建会话"清空当前上下文 |
| 5 | 导出 | 点击"导出笔记"，下载 .md 文件 |

### 3.5 效果反馈

**触发条件**：运行完成后想评价效果
**目标**：沉淀"哪些 skill/配方有效"的数据

```
[分析卡片/运行详情] → [对某个步骤打星+备注] / [对最终报告打星+备注]
  → [保存反馈]
```

**步骤说明**

| 步骤 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 1 | 在步骤卡片右下角点星级 | 星级高亮，展开备注输入框 |
| 2 | 填写备注（可选） | - |
| 3 | 点击"保存" | Toast"反馈已保存"，星级持久化 |

## 4. 页面设计

### 4.1 工作台（核心页面，输入驱动）

**路径**：`/`
**目的**：产品主工作区——居中输入商业想法，下方卡片流呈现所有分析会话
**入口**：默认首页、侧边栏"工作台"

**页面结构**
```
┌──────────────────────────────────────────┐
│  可行实验室                    [⚙ 设置]   │
├──────────────────────────────────────────┤
│                                          │
│      ┌──────────────────────────────┐    │
│      │  💡 输入你的商业想法，@ 引用配方  │    │
│      │  [ 我想做一个 AI 定价分析工具…    ] │    │
│      │  [@新项目可行性分析 ✕]           │    │
│      │          [开始分析 ▶]           │    │
│      └──────────────────────────────┘    │
│                                          │
│  ── 分析工作区（竖版卡片网格 ≥3 列）───   │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │
│  │ 📊 新项目 │ │ 📄 竞品对 │ │ 🧪 定价测 │ │ 📈 增长模 │ │
│  │ 可行性分析 │ │ 标分析  │ │ 算     │ │ 型      │ │
│  │ ● 执行中 │ │ ✓ 已完成 │ │ ⏸ 已跳过 │ │ ✓ 已完成 │ │
│  │ ▓▓▓ 3/5 │ │ ★★★★☆ 4 │ │ ★★★☆☆ 3 │ │ ★★★★★ 5 │ │
│  │ ①✓ ②● ③ │ │ 报告摘要… │ │ 报告摘要… │ │ 报告摘要… │ │
│  │ ④ ⑤    │ │         │ │         │ │         │ │
│  │ [展开]  │ │ [展开][导出]│ │ [展开]  │ │ [展开][导出]│ │
│  └────────┘ └────────┘ └────────┘ └────────┘ │
└──────────────────────────────────────────┘
```

**核心元素**

| 元素 | 类型 | 说明 |
| --- | --- | --- |
| 居中输入框 | 大输入框 | 支持多行；输入 @ 弹出配方选择器（模糊搜索），选中插入配方标签；位于深色 hero 瓦片上形成明暗对比 |
| 配方标签 | 可删除 Token | @配方名，点击 ✕ 移除；单次分析一个配方 |
| 开始分析按钮 | 主要按钮 | 未引用配方时弹确认选择框 |
| 分析卡片 | 竖版卡片 | 每次运行一张；**纵向排版**：顶部配方名 + 状态徽章 → 进度条 → 步骤时间线 → 实时摘要 → 底部操作区；多列网格布局，**始终 ≥3 列**（宽屏 4 列、桌面 3 列，窄屏压缩卡片宽度而非降列） |
| 卡片操作 | 按钮 | 展开详情 / 导出 MD / 评分 |

**状态设计**
- 空状态：输入框下方引导文案 + "还没有分析，输入一个想法开始吧"；无配方时提示"先在配方页编排一个配方"
- 加载中：输入框骨架；执行中卡片进度条动画
- 错误状态：卡片显示失败原因 + 重试/跳过；无 Key 时输入框旁 Alert 引导去设置
- 正常状态：输入框 + 竖版卡片网格（新卡片插入网格首位）

## 7. 设计系统

> 视觉基准：`DESIGN.md`（Apple 设计语言分析）。核心信条：**单一强调色 · 无装饰阴影 · 无渐变 · 明暗瓦片交替 · 大留白 · pill 即动作**。

### 7.1 颜色

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| Action Blue（主色） | `#0066CC` | 唯一交互强调色：所有按钮/链接/焦点环/标签 |
| Focus Blue | `#0071E3` | 键盘焦点环（2px outline）与选中态边框 |
| Sky Link Blue | `#2997FF` | 深色瓦片上的链接与 @标签（仅深色面使用） |
| Canvas（画布） | `#FFFFFF` | 主内容背景 |
| Parchment（羊皮纸） | `#F5F5F7` | 交替区段、侧边栏、次级背景 |
| Pearl（珍珠） | `#FAFAFC` | 次级按钮/徽章填充 |
| Dark Tile 1 | `#272729` | 深色区段（工作台 hero、页脚） |
| Dark Tile 2 | `#2A2A2C` | 相邻深色区段微差 |
| Dark Tile 3 | `#252527` | 日志面板、嵌入区域 |
| Ink（墨色） | `#1D1D1F` | 浅色面上所有标题与正文 |
| Ink Muted 80 | `#333333` | 珍珠按钮上的正文 |
| Ink Muted 48 | `#7A7A7A` | 次要信息、禁用态、时间戳 |
| Hairline | `#E0E0E0` | 1px 卡片描边（rgba(0,0,0,0.08)） |
| Divider Soft | `#F0F0F0` | 次级按钮软环（rgba(0,0,0,0.04)） |
| 成功 | `#34C759` | 状态：完成（Apple 系统绿） |
| 警告 | `#FF9500` | 状态：跳过/提示（Apple 系统橙） |
| 错误 | `#FF3B30` | 状态：失败/危险（Apple 系统红） |

### 7.2 字体

字体栈：`system-ui, -apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", Inter, sans-serif`（macOS/iOS 解析为真 SF Pro；非 Apple 平台回退 Inter，显示级字号 letter-spacing 再收紧 -0.01em）。

| 级别 | 大小 | 字重 | 行高 | 字距 | 使用场景 |
| --- | --- | --- | --- | --- | --- |
| Hero Display | 56px | 600 | 1.07 | -0.28px | 工作台大标题（预留） |
| Display Lg | 40px | 600 | 1.10 | 0 | 页面/区段大标题 |
| Display Md | 34px | 600 | 1.47 | -0.374px | 区块标题 |
| Lead | 28px | 400 | 1.14 | 0.196px | 副标题、引导文案 |
| Tagline | 21px | 600 | 1.19 | 0.231px | 卡片标题、导航分类 |
| Body | 17px | 400 | 1.47 | -0.374px | 正文（不用 16px） |
| Body Strong | 17px | 600 | 1.24 | -0.374px | 强调正文 |
| Caption | 14px | 400 | 1.43 | -0.224px | 说明、按钮文字 |
| Caption Strong | 14px | 600 | 1.29 | -0.224px | 强调说明 |
| Fine Print | 12px | 400 | 1.0 | -0.12px | 时间戳、辅助信息 |
| Nav Link | 12px | 400 | 1.0 | -0.12px | 导航项 |
| Code | 13px mono | 400 | 1.4 | 0 | 日志、JSON、Prompt |

规则：显示级标题一律 **600 字重 + 负字距**（"Apple tight"）；正文恒为 400/17px；字重阶梯 300/400/600/700，**无 500**。

### 7.3 间距（8px 基准）

| 级别 | 数值 | 使用场景 |
| --- | --- | --- |

| lg | 24px | 卡片内边距 |

| xxl | 48px | 大区段 |
| section | 80px | 全宽瓦片垂直内边距 |

### 7.4 圆角

| Token | 值 | 使用场景 |
| --- | --- | --- |
| none | 0px | 全宽瓦片（工作台 hero、页脚） |
| sm | 8px | 深色工具按钮、日志面板 |
| md | 11px | 珍珠胶囊按钮 |
| lg | 18px | 卡片、聊天气泡、大输入框 |
| pill | 9999px | 主/次按钮、搜索框、@标签——**动作信号专用** |
| full | 9999px / 50% | 头像、圆形图标按钮 |

### 7.5 阴影与层级

- **全系统只有一个阴影**：`rgba(0,0,0,0.22) 3px 5px 30px`，仅用于"产品影像"悬于表面（本项目无产品摄影，实际不启用）
- UI 层级来自：**表面色交替**（白/羊皮纸 ↔ 近黑瓦片）+ **1px hairline** + `backdrop-filter: blur`（粘性条、弹窗遮罩）
- 禁止：卡片/按钮/文字上的阴影、装饰性渐变、硬边框装饰

### 7.6 头像

| 尺寸 | 数值 | 使用场景 |
| --- | --- | --- |
| sm | 24px | 列表、选择器 |
| md | 48px | 人格卡片 |
| lg | 80px | 人格详情页头部 |

均为正圆（full radius）。
